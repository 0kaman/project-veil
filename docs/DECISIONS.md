| 2026-07-24 | **Render wired into read's escalation — by injection, so @veil/read stays browserless.** `veil_read` fetches; on a js-shell or doorman it escalates to a `RenderFn` (headless Chrome runs the JS), re-extracts, and the receipt says `via: render`. @veil/read never imports @veil/core — it accepts an injected `RenderFn`; @veil/mcp's server wires a @veil/core `Renderer` in. Both tiers run the SAME extractor/thresholds (`classifyHtml` refactored tier-agnostic); only `via` differs. Escalate on js-shell (content behind JS) AND doorman (headless Chrome's real TLS fingerprint may beat a fetch-blocking server). One Renderer per server process (Chrome lazy, held open, closed on SIGINT/SIGTERM). **Verified live through the real stdio server:** `veil_read` on reddit.com/r/programming auto-escalated → `via: render · 6702ms · ok · 103 words`. 6 hermetic escalation tests (fake renderer). The tool description now tells the model js-shell/doorman auto-escalate, and to give up only on "blocked both ways". | `@veil/read` (RenderFn), `@veil/mcp` (server) |
| 2026-07-24 | **`@veil/core` first slice: RENDER, not the behavior graph. The engine has two jobs — render a js-shell (browser as a renderer for READ) and act on a page (behavior graph + interaction) — and they're separable.** `Renderer.render(url)` launches headless Chrome (lazy, one browser, a fresh target per render), settles (network-idle, young-request-aware — the v1 quiescence-cap fix built in at the source), strips the `HeadlessChrome` UA token, and returns rendered HTML. Zero runtime deps (pure CDP over global WebSocket). Never throws — failure is `{ ok:false, error }`. Reuses v1's hardened cdp-client + launcher, with two measured fixes: **no `--disable-gpu`** (it removed WebGL, a bot tell no real Mac Chrome has) and **no self-contradicting UA** (v1 claimed Chrome/131 on a 150 binary while Sec-CH-UA reported 150). | Render is the cheapest engine capability, it closes the `js-shell` escalations the metric counts, it reuses @veil/read's extractor (engine renders → read extracts prose — the reboot's separation), and it lays the CDP foundation the behavior graph needs anyway. The flight-form (interaction) case is a later slice. **Verified live:** Reddit /r/programming — plain fetch gets 6 words (js-shell), render gets **1,722** (6.4s). | 2026-07-15 | **A browser is a fallback, not a foundation. Every task starts as HTTP.** Booting Chrome costs **969MB, 8 processes and 2,116ms** before one byte is read, and caps concurrency at ~10 sessions. You need it for exactly two things: the bytes don't exist until JS runs, or the server refuses non-browsers. Everything else is ~32× cheaper without it. So the engine is summoned, never assumed. | This is the move Dia/Comet/Atlas **structurally cannot make** — a human is watching their pages, so they must render everything, always. Veil has no viewport. Declining to boot is the payoff of the AI-first bet, and it's larger than the token efficiency we originally claimed for it. | [[ARCHITECTURE]] "The one idea" |

| 2026-07-15 | **Learn once, then replay. | 2026-07-15 | **`@veil/read` owns the dependencies; `@veil/core` stays zero-dep.** parse5 + linkedom + @mozilla/readability. | The zero-dep rule survives by **not applying** to the new package rather than by being broken. | 2026-07-15 | **Politeness: 10 global / 2 per-host concurrent, ~300ms spacing, 10s timeout, 1 retry on 429/503, real Chrome UA.** | Ten search results are usually ten domains, so per-host rarely binds — it's the brake for when a task hammers one site. **The tension, named:** politeness says identify as a bot, access says look like Chrome; you cannot do both. | 2026-07-15 | **Crawler parked, not cancelled.** Crawl a site → map its API surface → expose it for direct calls. | Strategically the strongest idea on the table and the natural extension of Stage 3 + replay: it would turn the browser from a per-task cost into a **per-site, one-time** cost, and nobody else is near it. Parked because the runtime has to exist first, and because it has real constraints to design for: **coverage is partial by construction** (crawling surfaces GETs; the POST behind a validated form never fires), API discovery *requires* the engine (~4s + 969MB per page, so a 1,000-page site is over an hour and needs bounds), and one sighting of an endpoint is not a schema. | — |

## Post-mortem: what v1 measured (code at `9e9f3e0`)

| finding | evidence |
|---|---|
| **The pipeline was never slow.** | Full decomposition of google.com: **211ms**. The other ~14s was `awaitQuiescence` burning its cap. |
| **Settle required `pending === 0`, which real sites never reach.** | Google's autocomplete XHR (`/complete/s`) never fires `loadend` → counter pinned at 1 → every action burned the full 12s cap. Fixed for the network half (`VEIL_LONGPOLL_MS`, id-keyed in-flight tracking): google.com **14,090 → 4,080ms**. The **DOM half still fires** — `domQuiet` is unreachable on animated pages (diabrowser.com: 17.8s with *zero* requests in flight). "Wait for quiet" is the wrong model, not a wrong constant. |
| **The behaviour graph is excellent for acting and blind for reading.** | github/login: **30 nodes, 1,013 tokens**, with `POST /session` attached — nothing else gives an agent that. wikipedia/HTTP: **800 nodes (capped), 18k tokens, 18% behavioural**. zapier article: **405 nodes, 0 prose**; the longest string in 11,355 tokens was the author's bio, harvested from a link's accessible name. |
| **The agent contributed the nouns; the model's weights contributed everything else.** | Across 7 pages the graphs named Dia/Comet/Atlas/Fellou/Genspark/BrowserOS (all present as link text). **"Chromium" — the load-bearing claim of the whole answer — appears 0 times in the pages and 17 times in the answer.** The browser delivered ~7 proper nouns for 104.3s and 43,736 tokens. |
| **CDP is exonerated.** | It ran thousands of AX/listener queries in 211ms, and it was the instrument that caught every bug — `Network.requestWillBeSent` proved Chrome had **0 requests in flight** while Veil's counter said 1. The friction was never the protocol; it was booting a browser for jobs that didn't need one. |
| **A browser is a credential, not just an engine.** | Measured JA3/JA4 on the same machine, seconds apart: curl `375c6162…` / `t13d4907h2` (49 ciphers, 7 extensions) vs Chrome `aa99bba3…` / `t13d1516h2` (15 ciphers, 16 extensions). The TLS ClientHello decides it **before a single HTTP byte**; header spoofing cannot touch it. Headless Chrome's JA3 is identical to headed Chrome's — which is exactly why booting it gets through the door and curl gets a CAPTCHA. |

## Open / scoped future work

- **The DOM half of the settle cap.** Still 12s per action on animated pages. Needs
  a different model (perceive immediately, update incrementally), not a bigger cap.
- **The doorman beats headless too.** Cloudflare fingerprints headless Chrome.
  Veil says `BLOCKED both ways` and stops. Stealth is not a workstream until it
  must be — but note v1's disguise was *actively broken*: UA claimed Chrome 131 on
  a 150 binary (and `Sec-CH-UA`, which `--user-agent` does not override, reported
  the real 150 — a self-contradiction no real browser produces), and
  `--disable-gpu` removed WebGL entirely, which no real Mac Chrome does. Layers
  3–4 are why you need a browser; layers 5–7 are where v1 threw that away.
- **CDP vs WebDriver BiDi.** Portability and a real standard, against capability —
  BiDi has no async initiator stacks today, and those are what make Stage 3 (the
  moat) possible. Staying on CDP; worth an argument, not a default.
- **Cross-origin iframes (OOPIF)** — `Target.setAutoAttach` + per-frame sessions +
  frame-namespaced ids. Designed in v1, never built.
- **The crawler** — see the row above.
