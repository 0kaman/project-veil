04 — Inside the Engine
How the pieces connect under the hood

Raw Chrome DevTools Protocol. No Playwright. No Puppeteer. Direct CDP commands give us fine-grained control over every aspect of the browser.

🔌
CDP Connection
Direct WebSocket to Chromium's DevTools Protocol. We subscribe to domains individually — only enabling what each pipeline stage needs.
Accessibility.getFullAXTree → Stage 1
Debugger.enable → Stage 2 events
Network.enable → Stage 3 correlation
Runtime.evaluate → React Fiber walk
DOM.getDocument → mutation root
⚡
Event Discovery
Finding what a button actually does. React uses event delegation — one listener on the root. We traverse the Fiber tree to find real component handlers.
DOM node → __reactFiber$ property
Walk Fiber.memoizedProps → onClick
Classify: navigation, state change, API call
Vanilla: getEventListeners() CDP
Result: edges connecting nodes to effects
📡
Network Correlation
When a button triggers an API call, we link them. CDP provides initiator stack traces that we match to nodes.
Network.requestWillBeSent event
Initiator.stackTrace → backendNodeId
URL pattern inference: /users/{id}
JSON body shape: {key: type}
Result: NetworkEdge per API call
👁
Mutation Detection
Pages change constantly. AJAX loads, SPA navigations, animations. MutationWatcher debounces DOM changes and triggers graph rebuilds.
Page.addScriptToEvaluateOnNewDocument
MutationObserver injected pre-page-load
150ms debounce window
Suppress during interact() calls
Diff-based graph patch (not full rebuild)
🆔
Display IDs
Chrome AX node IDs are opaque numbers. We generate human-readable IDs like button-log-in that LLMs can reference in tool calls.
Format: {role}-{name-slug}
Deduplication: -2, -3 suffix
Bidirectional map: display ↔ internal
Stable across graph rebuilds
Short, memorable, action-descriptive
🔄
Interact & Rebuild
When an LLM calls veil do click button-log-in, Veil clicks, waits for the page to settle, then rebuilds the graph.
1. Resolve display ID → AX node ID
2. DOM.resolveNode → objectId
3. Input.dispatchMouseEvent
4. Suppress MutationWatcher
5. Wait for network idle + DOM settle
6. Full pipeline re-run → new graph
05 — Session Persistence
Multi-step workflows that survive

Each CLI invocation reuses the same Chromium session. Cookies, localStorage, DOM state — all persist. Type username in one call, password in the next, click login in the third.

1
veil open instagram.com
8d060512-c7e1-4418-99fd-0312aeb2c487
UUID on stdout, daemon auto-starts if needed
2
veil do $SID type textbox-username _amxn5
PAGE https://instagram.com "Instagram" textbox-username [textbox] value: "_amxn5"
3
veil do $SID type textbox-password ••••••
Session retains username from step 2
4
veil do $SID click button-log-in
PAGE https://instagram.com/accounts/login/two_factor → Navigated! Session persisted across 3 CLI calls
5
veil graph $SID
PAGE https://instagram.com/ "(4) Instagram" textbox-security-code [textbox] "Security code" button-confirm [button] "Confirm"
2FA page — browser state fully preserved

07 — CLI Reference
Every command at a glance

Session-based commands for LLM agents. Legacy one-shot commands for humans. Short session ID prefixes supported.

🚀
veil open <url>
Open URL in persistent session, print UUID to stdout
📋
veil sessions
List all active sessions with IDs and URLs
🌳
veil graph <id> [--json]
Print behavior graph — compact text or JGF format
⚡
veil do <id> <action> <nodeId>
Interact with node — click, type, clear, select, focus, hover
🔍
veil find <id> <query>
Search nodes by role, name, or event type
🔬
veil inspect <id> <nodeId>
Show detailed node info — state, events, semantic label
🧭
veil navigate <id> <url>
Navigate within session, get updated graph
✕
veil close <id | --all>
Close session(s) and release browser resources
⚙
veil daemon start|stop|status|restart
Manage background daemon lifecycle
📡
veil decompose <url>
Legacy — one-shot decompose, no session persistence
💬
veil shell <url>
Legacy — interactive REPL with tab completion
🎯
veil interact <url> <nodeId> <action>
Legacy — one-shot interact, no persistence
